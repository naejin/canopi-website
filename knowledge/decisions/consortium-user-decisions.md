## Owner decisions, 2026-11-19 (after PP-C went live)

PP-C is live at master 398558aa. The owner agreed these on 2026-11-19; they bind the next work (target-structure plan, commit 0, board updates, the one-pool stream, then PP-D).

- **One pool everywhere.** A climate list is a label and a preference, never a scope: everything the palette shows, counts or picks from is the whole release pool, judged by fit for a period. Where the tool picks (Suggest, Next step, bulk adds), list plants that fit come first and other fitting plants only fill a gap, labelled; where the grower chooses (Find, See all, Swap, Paste), all plants, list plants first. One count: "N plants, M on your list". Placement by one function `placementFor(plant, place, period)`: the grower's list, else the list of the climate the place will have in the period, else the plant's nearest list (later canopi-data's plant defaults). Without a location, "Listed for your climate" is on by default and other plants say "not checked: give a location". The guest path (guest pools, "Look in another climate's list", guest labels, the guest share-link segment) is deleted. Today's code: `src/islands/palette/store.ts` (`store.pool`).
- **No browser country guess.** The country comes only from the grower (a location, a choice or a link), never from the time zone or browser languages: `guessCountry`, the guess branch at start, the build-time zone table, the "guessed" source and words go in commit 0. With no country, invasive warnings say "Recorded invasive in N countries" in words. "Use my location" stays (a tap and the permission). Local gates run under `TZ=UTC` like CI. Today's code: `src/islands/palette/state/arrival.ts`, `src/lib/palette/country-zones.ts`.
- **Island architecture.** (1) Persistence rewrite: two stored records, each with one owner (palette: plants, climate, choices; place: location and the grower's answers); a shared link opens as an overlay until "Use it"; load, reconcile and save as pure functions tested by a Node scenario matrix (save, place, link, reload, Forget, Start over, new cell), replacing `state/arrival`, `restore`, `persist`, `draft`, `save` and `schema`. (2) `store.ts` split by domain (data and pool, place, palette with undo, checks derived from the engine, UI), one-way flow views → actions → domain → derived. (3) Thin views over pure view models. (4) One lazy-part pattern, in the speed step. Today's code: `src/islands/palette/state/`, `src/islands/palette/store.ts`.
- **Stack stays.** Astro, Preact islands, pure CSS, static Cloudflare. SQLite-WASM stays: the speed step works around it (load timing, worker, caching) and never proposes replacing it or a new export format.
- **Preact component-test tier.** A fast tier of component tests in a simulated DOM under the existing test runner, added in commit 0; the browser suite keeps layout, late-font shift, contrast and walk-throughs.
- **PP-D process.** (1) Merge each builder batch once its fast gates are green, with the full gates running on integration; (2) commit 0 removes shared hotspots: no barrel re-exports from `src/lib/palette/index.ts`, each component imports its own CSS, one `store.ts` owner per chunk, a per-stream unused-locale-key check; (3) a script diffs each screen against its board (sizes, spacing, words, order), agent review keeps behaviour only; (4) fewer lasting tests: engine and store units, one board test per screen, round-named browser cases pruned when their screen is done; (5) the 11-language layout and late-font shift test, dark theme and contrast from the first screen; (6) the size change printed per merge with its cause, never a failure; (7) push each chunk once its gates are green. The flaky browser cases are made deterministic in commit 0 (wait on the app's ready signals, never on timing; one retry is not a fix).
